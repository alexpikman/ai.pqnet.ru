# Протокол: добавить тип события
> Серверная схема события и запись находятся в [chat/conversation_store.py](../../../chat/conversation_store.py).
> Runtime эмитит события через `AgentRuntime._emit`, который сохраняет их до публикации.
> Доставка браузеру выполняется через EventHub и SSE endpoint в `server.py`.
> Клиентская интерпретация событий находится в [frontend/chat-renderer.js](../../../frontend/chat-renderer.js).
> Новое событие требует согласованного изменения сервера, клиента и тестов.

## Шаги
1. Определи тип, payload, обязательные поля, идентификаторы связи и версионирование.
2. Добавь эмиттер в runtime; не публикуй событие в обход ConversationStore.
3. Сохрани порядок: append в журнал → EventHub.publish → SSE delivery.
4. Уточни replay: событие должно корректно отображаться при загрузке истории, а не только в live stream.
5. Если событие влияет на sequence/epoch, не меняй смысл метаданных без миграции и тестов.
6. Обработай событие в `ChatRenderer.apply` либо документируй, почему UI его игнорирует.
7. Для пользовательского текста используй textContent/DOM API, не вставляй необработанный текст модели через innerHTML.
8. Добавь тесты payload, порядка записи/публикации, повторов, replay и ошибок.
9. Проверь reconnect/sequence-gap и поведение при переполнении очереди EventHub.
10. Обнови glossary, архитектуру и test map.
