# AgentRuntime
> Реализация: [chat/agent_runtime.py](../../../chat/agent_runtime.py).
> Runtime выполняет ход агента, собирает историю из журнала и обрабатывает ответы провайдера.
> События создаются через Store, затем публикуются через EventHub.
> Runtime хранит дедупликацию command_id и активные задачи в памяти процесса.
> Отмена реализована через threading.Event и проверяется в ходе выполнения, но её end-to-end UX нужно оценивать отдельно.

## Назначение
Оркестрация одного хода чат-агента: контекст, потоковые фрагменты, вызовы инструментов, подтверждения, финальные события и ошибки.

## Основные контракты
- `AgentRuntime(store, hub, provider, tool_executor, agent_config, max_steps=12)`
- `cancel_task(task_id) -> bool`
- Внутренний `_emit` сначала вызывает `store.append_event`, затем `hub.publish`.
- Остальные внутренние методы не являются стабильным публичным API; читай сигнатуры напрямую перед правками.

## Инварианты
- Runtime связан с ConversationStore, EventHub и адаптером провайдера.
- Секреты проходят best-effort redaction перед долговременной записью.
- Вызовы инструментов ограничены max_steps и обработкой результата.
- Терминальные события должны соответствовать контракту статусов в тестах.
- Не считать обычный разговор технической задачей, требующей обязательной verification, без проверки текущего условия в коде.

## Зависимости
`chat.conversation_store`, `chat.chat_events`, `chat.provider_adapter`, callback исполнения инструмента; стандартная библиотека.

## Тесты
[tests/test_chat_agent_runtime.py](../../../tests/test_chat_agent_runtime.py) — runtime событийного чата, статусы, tool flow и verification gate по текущим assertions.
