# Chat events and EventHub
> Реализация доставки: [chat/chat_events.py](../../../chat/chat_events.py).
> EventHub хранит очереди подписчиков в памяти процесса и не является постоянным хранилищем.
> Runtime должен append-ить событие в ConversationStore до вызова publish.
> HTTP SSE endpoint и replay реализованы в `server.py`.
> Клиент использует sequence/epoch для обнаружения пропусков и восстановления истории.

## Назначение
Разделяет долговременное хранение событий и временную доставку браузерным подписчикам.

## Контракт
- `EventHub()`
- `subscribe(conversation_id) -> queue.Queue`
- `unsubscribe(conversation_id, q)`
- `publish(conversation_id, event)`

## Инварианты и ограничения
- Очередь каждого подписчика ограничена 256 событиями.
- Публикация неблокирующая; при переполнении событие не помещается в очередь, а пишется сообщение в stderr. Клиент должен восстановить пропущенное из журнала.
- Подписчики и очереди существуют только в памяти.
- SSE — однонаправленный поток. Команды идут отдельными POST-запросами.
- Не добавляй бизнес-состояние только в EventHub: источник истины — ConversationStore.

## Зависимости
Стандартные `queue`, `threading`, `typing`.
