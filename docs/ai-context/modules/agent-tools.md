# Инструменты агента
> Реализация: [agent_tools.py](../../../agent_tools.py).
> Реестр описывает операции чтения, поиска и изменения файлов, а также интеграционные действия.
> Файловые операции должны проходить проверку разрешённых корней и соответствующих разрешений.
> Встроенный docstring явно не обещает shell, PowerShell, SSH или произвольный Python execution как доступные инструменты.
> При расширении инструментария проверяй definition, executor, permission checks и тесты.

## Назначение
Предоставляет runtime инструменты с ограничением корней доступа, размеров файлов и типов файлов для поиска.

## Реестр и параметры
- `TOOL_DEFINITIONS` — схемы функций, передаваемые модели.
- `effective_tools(...)` — фильтрация набора инструментов с учётом конфигурации/разрешений (точную сигнатуру смотри в исходнике).
- `execute_tool(...)` — исполнение инструментального вызова (точную сигнатуру смотри в исходнике).
- В исходнике определены, среди прочего, `list_files`, `read_file`, `search_files`, `write_file`, `move_file`, `delete_file`, `create_directory`; набор нужно проверять по актуальному реестру.

## Защитные ограничения
- `MAX_TEXT_BYTES = 1_000_000`, `MAX_SEARCH_FILES = 200`.
- Блокируются распространённые каталоги зависимостей/метаданных: `.git`, `node_modules`, виртуальные окружения и другие элементы `BLOCKED_DIRS`.
- У файлового доступа есть явные разрешённые корни; не обходи проверки нормализацией путей или symlink.
- Удаление требует явного `file_deletion` permission согласно описанию инструмента.
- Не называй это полноценным sandbox ОС.

## Зависимости
Стандартные `pathlib`, `os`, `json`, `urllib`, `subprocess`, `socket`, `ipaddress`, `shlex`, `typing`.
