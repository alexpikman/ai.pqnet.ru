# ConversationStore
> Реализация: [chat/conversation_store.py](../../../chat/conversation_store.py).
> Store хранит события по диалогам в файловом хранилище и восстанавливает метаданные при старте.
> Запись события сериализуется в JSONL; повреждённый хвост журнала может быть восстановлен.
> Sequence и epoch нужны для повторного чтения и обнаружения разрывов в клиенте.
> Блокировки обеспечивают согласованность внутри одного процесса, не между несколькими процессами.

## Назначение
Долговременный журнал событий одного диалога, чтение истории и восстановление sequence/epoch после перезапуска.

## Публичный контракт
- `ConversationStore(data_dir: Path)`
- `append_event(conversation_id, event_type, payload, task_id=None, message_id=None, tool_call_id=None)`
- Методы чтения истории/событий и служебные методы доступны в исходнике; перед вызовом сверяй точные сигнатуры, так как это внутренний API.

## Инварианты
- ID диалога проходит валидацию и начинается с `conv_`.
- Каталог диалога проверяется на выход за пределы корня хранилища.
- События записываются построчно в JSONL с метаданными, включая sequence и epoch.
- Атомарные JSON-файлы пишутся через временный файл и `os.replace`.
- Runtime должен записать событие прежде, чем оно будет опубликовано через EventHub.

## Зависимости
Стандартная библиотека: `json`, `os`, `threading`, `uuid`, `datetime`, `pathlib`, `typing`.
