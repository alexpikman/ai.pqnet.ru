# Server API
> Основной сервер: [server.py](../../../server.py), entry point использует `ThreadingHTTPServer` и `SimpleHTTPRequestHandler`.
> Приложение по умолчанию слушает `127.0.0.1` и порт `8765`, порт переопределяется `PQ_PORT`.
> `server.py` связывает REST API с ConversationStore, EventHub, AgentRuntime и OllamaAdapter.
> Статические файлы frontend отдаются тем же HTTP-сервером.
> Для точных маршрутов и методов всегда смотри актуальные ветки обработчика в исходнике.

## Назначение
HTTP entry point для UI, настроек, сущностей приложения, инструментов, авторизации и событийного чата.

## Архитектурные факты
- Импорты в начале файла: stdlib HTTP сервер и стандартные библиотеки.
- Глобальные chat services: `CHAT_STORE`, `CHAT_HUB`, `CHAT_PROVIDER`, реестры runtime/активных команд.
- `_chat_runtime_for` настраивает runtime и явно проверяет `provider.get('format') == 'ollama'`.
- `HOST = '127.0.0.1'`; `PORT` читается из `PQ_PORT`.
- В `server.py` есть optional imports `llama_cpp` и `huggingface_hub`; они не означают zero-dependency для каждой функции.

## API для чата
Изучай обработчик маршрутов и связанные методы для точных схем:
- история и события чата;
- POST отправки команды;
- решение запроса подтверждения;
- отмена задачи, если маршрут присутствует в текущей версии.
Не полагайся на неактуальный список endpoints из старых документов.

## Авторизация и безопасность
В проекте есть auth-логика; режим и ограничения нужно сверять с текущими `AUTH_ENABLED`, `auth.js` и API-обработчиками. Не обещай, что все endpoints закрыты одинаково, без аудита маршрутов. Локальная привязка не заменяет проверку permission-gated операций.
