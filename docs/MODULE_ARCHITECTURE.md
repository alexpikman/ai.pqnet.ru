# Архитектура модулей

## Цель

PQlocalAgentOSv3 — модульная локальная платформа. Ядро отвечает за интерфейс, конфигурацию, реестр страниц и меню, поиск расширений, управление связями и безопасные границы исполнения.

## Структура

- `frontend/` — общий интерфейс и визуальный конструктор.
- `server.py` — локальный API без сторонних Python-зависимостей.
- `modules/<module-id>/module.json` — локальный манифест каждого зарегистрированного модуля.
- `data/modules.json` — реестр модулей и связи текущего локального экземпляра.
- `data/settings.json` — общие настройки интерфейса и меню.
- `data/pages/index.json` — страницы, созданные через UI.

## Протокол модуля

Каждый модуль объявляет уникальный идентификатор, версию, версию API, входы, выходы, возможности и разрешения. Модуль должен быть независимым и не менять файлы ядра. Совместимость проверяется по контрактам входов и выходов, а не только по совпадению названий.

## Граф связей

Связи хранятся как направленные рёбра `from → to` с описанием назначения и портами `from_port` / `to_port`. API проверяет существование портов, совместимость типов, а также отклоняет самосвязи, дубликаты и циклы. Графовый исполнитель обходит узлы, достижимые от выбранного стартового модуля, и передаёт выходы по рёбрам. Для именованных входов доступны шаблонные переменные вида `{input.port_name}`; если в модуль сходятся несколько рёбер, входы передаются как объект по именам портов. Поддерживаемые встроенные типы: `input`, `template`, `ollama`, `transform`, `output`. Для `transform` доступны операции регистра, обрезки пробелов и разбора/форматирования JSON. `ollama` вызывает настроенный локальный сервис и сохраняет результат каждого шага. Внешний исходный код не исполняется.

## GitHub-каталог

Поиск использует GitHub Repository Search. Добавление репозитория создаёт локальную запись и формальный манифест. По отдельному подтверждению можно загрузить ограниченный набор текстовых исходников в подпапку `source` (до 100 файлов и 2 МБ); скачанный код остаётся неисполняемым и требует проверки. Перед полноценной установкой нужно проверить лицензию, зависимости, workflow, исходный код и разрешения. Никогда не исполняйте найденный код автоматически.

## Интерфейс и страницы

Общее меню, шапка и визуальные настройки принадлежат ядру и применяются к системным и пользовательским страницам. Модуль может объявить свои страницы через контракт, но использует общие компоненты и стили по умолчанию.


## Runtime AI-агентов

Для ролей определены базовые системные инструкции; пользователь может переопределить их в интерфейсе. Агент хранит пользовательские заметки в локальном реестре. Задача может ссылаться на проект; в prompt передаются его название, описание и путь как справочные метаданные. Файлы по этому пути автоматически не открываются. Модель выбирается из задачи либо из профиля назначенного агента. Выполнение остаётся синхронным вызовом локальной Ollama.


## Разрешения и инструменты агентов

Инструменты вынесены в `agent_tools.py`. Локальный доступ выключен по умолчанию. Для файлового доступа требуются одновременно: глобальное включение, хотя бы одна разрешённая папка и разрешение конкретного агента. Путь проверяется на принадлежность корню; символические ссылки и Windows junction блокируются. Чтение ограничено текстовыми файлами и размером 1 МБ; поиск ограничен числом просматриваемых файлов и результатами. Перемещение не перезаписывает существующую цель; удаление файлов и папок требует отдельного права. GitHub-инструменты доступны только при включённом `github_access` у агента и заданном `GITHUB_TOKEN`. Shell, PowerShell, SSH и запуск произвольных программ не реализованы.


## Командное выполнение задач

Для задачи можно включить командный режим: 1) менеджер формирует план и критерии готовности, 2) назначенный специалист выполняет задачу и может использовать только выданные ему инструменты, 3) контролёр качества оценивает результат и ограничения. Вывод каждого этапа, модель и число вызовов инструментов сохраняются в истории задачи. Этапы выполняются последовательно; это не параллельный запуск.
