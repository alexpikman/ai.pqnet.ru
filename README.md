# PQlocalAgentOSv3

**Локальная платформа управления AI-системами.** Модульная система с общим интерфейсом, конструктором страниц и меню, централизованными настройками оформления и каталогом расширений GitHub.

## Запуск в Windows

1. Установите Python 3.10+.
2. (Необязательно) Для GitHub API задайте токен в PowerShell в том же окне, откуда запускаете приложение:
   `$env:GITHUB_TOKEN="ваш_токен"`
   Для приватного репозитория нужен доступ к нему; для сохранения файлов — Contents: Read and write. Не сохраняйте токен в файлах проекта.
3. Запустите `start.bat`.
4. Откройте http://127.0.0.1:8765.

Можно переопределить порт через переменную окружения `PQ_PORT`. Сервер привязан к localhost и не открывает приложение напрямую в локальную сеть.

## Возможности текущего каркаса

- Общий frontend-шаблон и единый layout для системных и пользовательских страниц.
- Настройка темы, акцентного цвета, шрифтов, размеров, ширины боковой панели, отступов рабочей области и параметров шапки с сохранением на диск.
- Конструктор пользовательских страниц: создание, редактирование и удаление из интерфейса.
- Конструктор меню: изменение порядка, названий, видимости и вложенности пунктов, привязка к страницам.
- Модульный каталог: регистрация модулей в папке `modules/`, локальный реестр, описание контракта входов/выходов и схема связей между модулями.
- Создание и настройка локальных модулей из интерфейса: отдельная папка, `module.json`, README, редактирование встроенного runtime и именованных входов/выходов.
- Визуальная схема графа с именованными портами, проверкой типов и циклов, запуском цепочки и сохранением результатов.
- Ролевые AI-агенты с настраиваемыми системными инструкциями, долговременной пользовательской памятью и контекстом назначенного проекта при выполнении задач.
- Командный режим задач: менеджер планирует, назначенный специалист выполняет работу, контролёр качества проверяет результат; выводы этапов сохраняются в задаче.
- Инструменты агента с явными разрешениями: чтение/поиск, запись, перемещение и удаление файлов, управление папками, чтение GitHub. Доступ к локальным файлам по умолчанию выключен и ограничен явно разрешёнными папками.
- Исполнение направленных ациклических графов модулей с передачей результата между шагами, локальными преобразованиями текста/JSON и вызовом Ollama.
- Поиск GitHub-репозиториев из интерфейса, регистрация в локальном каталоге и ограниченная загрузка текстовых исходников для проверки.
- GitHub-интеграция для проверки подключения, чтения файлов и сохранения изменений отдельными коммитами.
- Локальный журнал событий и endpoint проверки состояния.
- Python backend без внешних зависимостей и автоматические проверки Python, JavaScript, JSON-схемы и модульного runtime.

## Важно о сторонних модулях

Поиск и добавление репозитория в каталог **не означает безопасную установку или запуск его кода**. Интеграция регистрирует источник и может скачать ограниченный набор текстовых исходников (до 100 файлов и 2 МБ) в подпапку `source` для проверки. Произвольный код не запускается автоматически. Агентам по умолчанию не предоставляются shell, PowerShell, SSH и возможность запуска произвольных программ. Инструменты `run_command` и `ssh_execute` включаются только через явные разрешения (`terminal_access`, `ssh_access`) и требуют подтверждения пользователя на каждое действие. Прямое выполнение кода через `powershell`/`shell`/`execute_python` не поддерживается. Файловые инструменты доступны только после включения глобального доступа, добавления разрешённой папки и выдачи отдельных прав конкретному агенту. Перед полноценной установкой необходимы проверка манифеста, лицензии, зависимостей, разрешений и изолированная среда исполнения. Графовый исполнитель запускает только явно поддерживаемые встроенные типы (`input`, `template`, `ollama`, `transform`, `output`); внешние модули без адаптера отклоняются.

Архитектура и контракт описаны в `docs/MODULE_ARCHITECTURE.md`, настройки меню — в `docs/INTERFACE_AND_MENU.md`, схема манифеста — `module-contract.schema.json`.

Локальные данные находятся в `data/` и не коммитятся. Установленные модули в `modules/<id>/` также исключены из Git по умолчанию.
## Шаблоны системных инструкций

Базовые промпты для восьми ролей хранятся в `agents/templates/{ROLE}.md`:
`MANAGER.md`, `ARCHITECT.md`, `ANALYST.md`, `DESIGNER.md`, `COPYWRITER.md`, `CODER.md`, `TESTER.md`, `DEVOPS.md`.

- При первом запуске сервер создаёт восемь инструкций в `data/system_instructions.json`, беря `system_prompt` из файлов шаблонов.
- Кнопка «По умолчанию» в модалке загружает актуальные `system_prompt` и `activity`; текущий `interaction_plan` при этом не изменяется.
- Файлы читаются при запросе `GET /api/system-instructions/defaults`, поэтому изменения на диске доступны без перезапуска сервера.
- Если файл отсутствует, пуст или не читается, используется встроенный fallback `SYSTEM_INSTRUCTION_PROMPTS` из `server.py`. При старте отсутствие файла записывается в журнал, сервер продолжает запуск.
- Шаблоны входят в репозиторий. Не помещайте в них секреты и не удаляйте каталог `agents/templates/`.
